# Pangolin code review — WTFs, refactorings, dead code, doc drift

Date: 2026-04-30. Branch: main @ 503b54c (v0.12.2).

Sorted by impact within each section. Every item has a `file:line` ref.

## A. WTFs / latent bugs

1. **`gh()` ignores its own `check=` parameter.** `src/pangolin/core.py:52`.
   Signature accepts `check: bool = True` and the docstring talks about it,
   but the body never uses it. Every call site that passes `check=False` is
   already getting the same behaviour every other caller gets. Either honour
   the flag (raise on `check=True && returncode!=0`) or delete the parameter
   and stop pretending.

2. **`load_modes()` will `AttributeError` on `None.parent` if `PANGOLIN_MODELS`
   is set + relative path + no `path` arg.** `src/pangolin/modes.py:341-347`.
   When `path is None` (the production code path), `cfg_p = path.parent / cfg_p`
   crashes. Tests pass `path` explicitly so this never fires in CI. Either
   drop the rel-path resolution against `path.parent` (it's nonsense when
   `path is None`) or resolve it against `Path.cwd()` / `default_modes_yaml().parent`.

3. **`REPO = _repo_root()` evaluated at import time.** `src/pangolin/core.py:14-22`.
   Importing `pangolin.core` outside a git repo crashes the package, including
   `pangolin version` and `pangolin init` (which scaffolds *into a possibly
   non-git dir*). Also can't be unit-tested without monkey-patching after
   import. Make `REPO` lazy.

4. **`_phase_wiki_ingest` reads `wiki/SCHEMA.md` directly.** `src/pangolin/orchestrate.py:1915`.
   No fallback, no `resolve_config()` lookup. If a wiki was scaffolded
   without `--with-wiki` and never copied SCHEMA.md, or the user deleted it,
   the entire wiki-ingest phase crashes. The package even ships
   `default_config/wiki_schema.md` for exactly this case — but the resolver
   isn't used. Switch to `resolve_config("wiki/SCHEMA.md")` and reconcile
   the file naming.

5. **`software.run()` never closes the picked-up `mode:software` ticket.**
   `src/pangolin/software.py:115-208`. Every cycle re-picks the same oldest
   open ticket via `gh issue list ... --limit 1`. Two consecutive cycles
   produce duplicate task branches/PRs for the same issue (or the second
   `git push` collides on the existing branch). Either close the ticket
   with a "continue via PR comments" message after PR creation (matching the
   `_phase_close_processed` pattern), or skip-if-PR-exists.

6. **The progress comment posted on the software ticket lacks `AGENT_MARKER`.**
   `src/pangolin/software.py:206-207`. Every other agent-authored comment
   wraps the body via `wrap_agent_body`. This one doesn't. If the ticket is
   ever closed and a future `auto_reopen_recent("mode:software")` is added,
   this comment looks like new owner activity and re-opens the ticket.

7. **CLI tools listed in `mode.allowed_tools` but not in `CLI_TOOL_NAMES`
   are silently dropped.** `src/pangolin/orchestrate.py:610-612`. A typo in
   modes.yml (`reed` for `read`) gives the agent zero tools, silently. At
   minimum: log a warning when the input is non-empty and the mapped output
   is empty.

8. **Confabulation marker substring match is over-broad.**
   `src/pangolin/orchestrate.py:1055-1069, 1095`. A legitimate citation
   containing the substring `"could not verify"` or `"unverified"` (e.g.
   quoting an editorial phrase) gets the whole finding rejected.
   Acceptable trade-off today, but the rejection log doesn't include the
   matching span. Add the matched substring to the log line so a maintainer
   can tell a real confabulation from a quoted phrase.

9. **Per-cycle module-level mutable state.** `_SENTINEL_CACHE`
   (`src/pangolin/orchestrate.py:119`) and `_PROXY_IP`
   (`src/pangolin/orchestrate.py:414`) are set on first use and never reset.
   Fine for one-shot CLI usage; breaks if `run_cycle()` is invoked twice in
   the same process (test harness, future "loop" mode). Reset both at the
   start of `run_cycle()` or hang them off `CycleRunner`.

10. **`harden_egress()` builds the proxy URL with the literal port `3128`.**
    `src/pangolin/orchestrate.py:2632`. Every other call site uses
    `_proxy_url(tier)` / `PROXY_PORT_TIGHT`. If the constants drift, the
    host-side `HTTPS_PROXY` exported to `$GITHUB_ENV` will silently disagree
    with what `_base_docker_flags` injects into containers. Use
    `_proxy_url("tight")`.

11. **`_build_mounts` `chmod 0o777` may be redundant for non-software modes.**
    `src/pangolin/orchestrate.py:542`. Justified for gVisor's gofer-9p
    UID-stripping, but `_base_docker_flags` runs containers as
    `--user $UID:$GID` (line 562), so on tight modes the host UID does
    match. Worth re-measuring whether the chmod is still needed for
    non-software modes; if not, drop it (silent permissive-mode bumps on
    user content dirs are noisy).

12. **`OWNER_LC` is exported but never consumed in the shim.**
    `src/pangolin/default_config/workflows/agent-cycle.yml:147`. The image
    pull on the next line hard-codes `ghcr.io/nila-loeber/$img`. Either use
    `${OWNER_LC}` in the pull URL (so a fork works) or delete the export.

## B. Dead code

1. **`_run_search_phase` (~50 lines).** `src/pangolin/orchestrate.py:990-1041`.
   Defined, never called. The active research-search path is
   `spawn_agent_container_direct` in `_phase_research`. Worse:
   `default_config/modes.yml:65-66` claims phase 1 is "hardcoded in
   orchestrate.py::_run_search_phase()" — a doc lie pointing at dead code.
   Delete the function and update the modes.yml comment + the in-test
   reference at `tests/test_security.py:1512`.

2. **`OpenAICompatProvider` (~63 lines) + the `scaleway` factory branch.**
   `src/pangolin/providers.py:195-272`. No mode in modes.yml uses
   `provider: scaleway`, no test exercises it, the implementation is
   incomplete (`tool_calls=0  # TODO`, `qwen3.5-397b` model name that
   smells made-up). Header comment in modes.yml lists `anthropic|scaleway`
   as valid, perpetuating the mirage.

3. **`denied_tools` config field.** `src/pangolin/modes.py:22, 372`,
   populated on every mode in `default_config/modes.yml`. Never read
   anywhere. Documented as "soft" enforcement; in practice no enforcement
   at all. Either delete the field everywhere or genuinely cross-check it
   inside `_validate_invariants`.

4. **`gh_cli` config field is half-dead.** `src/pangolin/modes.py:25,
   411-412`. Only checked for the untrusted+gh_cli combination, which never
   occurs (every untrusted mode ships `gh_cli: false`). Setting
   `gh_cli: true` on a trusted mode does nothing — no code path mounts a
   GH token into containers based on this field. Either wire it up
   (`-e GH_TOKEN=...` in `_base_docker_flags`) or delete it.

5. **`autonomy` config field.** Acknowledged in modes.yml as "documentation,
   not enforced". Nothing reads it. Drop, or repurpose as
   `description`-suffix metadata if a future `pangolin modes ls` subcommand
   wants it.

6. **Unused imports.** `src/pangolin/software.py:15` `import sys`,
   `src/pangolin/software.py:16` `from pathlib import Path`,
   `src/pangolin/orchestrate.py:28` `import sys`,
   `src/pangolin/software.py:146` `from pangolin.orchestrate import
   spawn_agent_container_tooluse` (the actual call lives inside
   `_spawn_and_verify`'s own local import).

7. **`tests/test_security.py:7`: `sys.path.insert(0, str(REPO / "scripts"))`.**
   No `scripts/` dir exists in the repo. Stale test setup.

8. **`scaffold.py:79-81` TODO block** duplicates BACKLOG.md's "Generalize
   nlkw's wiki conventions" entry. Pick one; keeping both invites drift.

## C. High-value refactorings

1. **Compress `apply_path_scoped_writes` indirection.** Module-level free
   function (`src/pangolin/orchestrate.py:1498`), then a one-line method
   `CycleRunner._apply_path_scoped_writes`
   (`src/pangolin/orchestrate.py:2354`) that just forwards. Same for
   `execute_writing_drafts` / `_execute_writing_drafts`. The methods exist
   only so test code can write `runner._apply_path_scoped_writes(...)`
   against an `__new__`'d runner. Either drop the methods (tests call the
   module function with `monkeypatch.setattr(O, "REPO", tmp_path)` already
   in place) or drop the free function and inline the logic on the method.
   Today both forms exist and the indirection adds zero value.

2. **Split `orchestrate.py` (~2650 lines).** The file owns: regexes/parsers,
   sentinel watermark, agent runners (in-process + container, direct +
   tooluse), proxy lifecycle, executors (gh actions, write appliers), eight
   cycle phases, and the `harden_egress` CLI implementation. Natural split:
   `proxy.py` (proxy lifecycle + harden_egress), `agent_run.py`
   (`spawn_*`, `_parse_stream_json`, `_count_tool_uses`), `cycle.py`
   (`CycleRunner` + phases). Tests import `from pangolin import orchestrate
   as O` everywhere — a thin re-export shim keeps them green.

3. **Pre-compile `CLI_NAME_TO_API_TYPE_PREFIX` once and host the policy
   in one place.** Today it lives in `tests/test_security.py:1381` and is
   duplicated implicitly by `pangolin_egress.LOOSE_PORT_TOOL_TYPE_PREFIXES`
   and the orchestrator's hardcoded `"WebSearch WebFetch"` strings. Move it
   to `pangolin_egress.py` (or a new `egress_policy.py`) and have both
   production code and tests import the same dict. Removes the structural
   drift the `TestSecurityPolicyCoherence` class itself acknowledges as
   "the bug we got bitten by".

4. **Stop interpolating the json-schema into the system prompt on the SDK
   path.** `src/pangolin/orchestrate.py:1276` (run_direct) wraps the schema
   into the system text as `Respond with a single JSON object matching this
   schema: {json}` even when the SDK path uses Anthropic Structured Outputs
   (which already constrains decoding). Wasted tokens. Let `providers.py`
   own the prompt-shape contract on the SDK path; pass the schema through
   the API kwargs only.

5. **Stop reading every CLI envelope's `result` through three different
   parsers.** `spawn_agent_container_direct`
   (`src/pangolin/orchestrate.py:929-944`), `_parse_json_array_from_text`
   (`src/pangolin/orchestrate.py:947-987`), `run_direct_agent` fallback
   (`src/pangolin/orchestrate.py:1180-1194`), `_phase_wiki_ingest` SDK
   fallback (`src/pangolin/orchestrate.py:2061`). All four do the same
   fence-strip + greedy-extract dance. Consolidate.

6. **Promote `_referenced_writable_files` from writing-only into the
   wiki-ingest phase.** `src/pangolin/orchestrate.py:1590`. wiki-ingest
   re-implements its own slug/issue scan
   (`src/pangolin/orchestrate.py:1960-2000`) for the same purpose ("if the
   task references a file, give the agent the actual content"). Share one
   helper with different `allowed_prefixes`.

7. **Split `_phase_wiki_ingest` (~220 lines).** It does: precondition
   check, fragment loading + capping, absorb-target heuristic with three
   sub-strategies, prompt assembly, dual agent dispatch (OAuth + SDK),
   write application, watermark advance, log entry, `pages_per_ticket`
   capture, validator. Extract `_load_fragments_capped`,
   `_pick_absorb_targets`, `_advance_watermark` so the security tests can
   assert each precisely.

8. **Replace the `# A:` / `# B:` comment markers in `_phase_summary`**
   (`src/pangolin/orchestrate.py:2458, 2493`) with named local helpers
   (`_skipping_no_pr`, `_only_trivial_changes`). The comment letters
   reference an out-of-band convention nobody else uses.

9. **Centralise the bot/agent-author check.** `_is_agent_author`
   (`orchestrate.py:191`), `_is_owner_comment` (`pr_feedback.py:48`),
   inline filters in `auto_reopen_recent` (`orchestrate.py:240-244`),
   `_phase_triage._has_new_activity` (`orchestrate.py:1721-1729`), and the
   shell `jq` filters in `agent-cycle.yml:95-96, 113-114` all encode "skip
   `[bot]`/`-agent` author + skip `AGENT_MARKER` body". One Python helper,
   exported. The workflow shim's two `jq` filters either call it via
   `python -c` or carry a code-pinned cross-ref comment.

## D. Documentation lies / drift

1. **CLAUDE.md:18 lists `pangolin init|run|harden-egress|version`.** Actual
   subcommands per `cli.py:24-63` are `init|cycle|run|harden-egress|refresh-workflows|version`.
   Two missing.

2. **CLAUDE.md:128 + default_config/modes.yml:9-10 claim invariants** that
   `_validate_invariants` does NOT enforce:
   - "readable_paths and writable_paths must be non-empty" — never checked.
     `research` mode actively has `writable_paths: []`, which would fail
     the doc's invariant if it were real.
   - "writable_paths must be a subset of readable_paths" — never checked.
   Either enforce both in `src/pangolin/modes.py:405-418` or remove the
   doc claims. Today they're the kind of "we promise this" lie that bites
   when someone trusts the doc instead of the code.

3. **default_config/modes.yml:65-66 says** phase 1 search is "hardcoded in
   orchestrate.py::_run_search_phase()". The actual phase 1 is the
   `spawn_agent_container_direct` call inside `_phase_research`
   (`src/pangolin/orchestrate.py:1808`). `_run_search_phase` is dead code
   (see B.1). Update the comment.

4. **default_config/modes.yml:25 lists** `provider: anthropic|scaleway`.
   `scaleway` is a dead-code provider (see B.2). Remove the option from the
   docstring.

5. **default_config/modes.yml:18 calls** `denied_tools` "soft" enforcement.
   It is no enforcement (see B.3). Delete the line or implement the
   enforcement.

6. **default_config/modes.yml:21 calls** `gh_cli` "whether a GitHub token
   is mounted". No code mounts a GH token based on this field (see B.4).

7. **default_config/modes.yml:31-35 says** loose tier "is hardcoded in
   orchestrate.py and sets loose directly". Phase 1 search is wired through
   `egress_tier="loose"` literal at `src/pangolin/orchestrate.py:1813`,
   which contradicts the spirit of "modes drive port selection". The
   research mode's own `egress: tight` field is then used for phase 2
   (`src/pangolin/orchestrate.py:1856`). Either accept the split (and
   update the comment to say "phase 1 hardcoded loose, phase 2 reads
   `mode.egress`") or unify by giving research a single canonical egress
   tier.

8. **CLAUDE.md:71-73** says "the addon's `request` hook strips any
   incoming Authorization header and injects `Bearer <token>` for
   `api.anthropic.com`". This is correct, but the next paragraph
   (CLAUDE.md:77-79) says "denied endpoints (batches, count_tokens, future
   beta paths, org-scoped routes) get a 403 without ever bearing the real
   OAuth token upstream". That's only true because the endpoint check at
   `src/pangolin/pangolin_egress.py:207-215` runs before the auth rewrite
   at line 219 — a structural ordering that test
   `test_endpoint_deny_precedes_token_injection` already guards. Worth a
   one-line cross-ref in the doc back to that test, since the ordering is
   the only thing making the claim true.

9. **README.md:24-28 says** "every agent call runs in a per-agent gVisor
   sandbox … and blocked egress outside a pinned allowlist". Strictly
   true for the *agent containers*, but `pangolin cycle` itself runs on
   the host and `harden_egress` *no longer* installs a host iptables
   REJECT (removed 2026-04-21, see `commit_and_pr` rationale comment in
   `src/pangolin/orchestrate.py:2604-2628`). The README's framing implies
   host-level lockdown that doesn't exist. Add one sentence: "host-side
   egress is governed only by `HTTPS_PROXY`; libraries that ignore the
   env var bypass the allowlist."

10. **CLAUDE.md:141-143 lists** end-to-end requirements as
    `GH_TOKEN + CLAUDE_CODE_OAUTH_TOKEN` from `/mnt/sandcastle/pangolin/test-pangolin/`.
    The test-pangolin canary path is environment-specific. Either move
    that paragraph to a personal scratchpad or rephrase generically
    ("from the canary wiki repo").

11. **CHANGELOG.md jumps from v0.1.0 (2026-03) directly to v0.11.0**
    (2026-04-28). Either v0.2.0 through v0.10.0 didn't exist (fine — say
    so) or they were rolled up. Add a one-liner explaining the gap, or
    drop the v0.1.0 entry entirely if it's nominal.

12. **README.md:130-138 commands list** does not match cli.py order or
    set: it omits nothing material but presents `cycle`, `run`,
    `harden-egress` in a different order from the CLAUDE.md list. Pick
    one ordering and use it in both places.

## Recommended attack plan

If you want a single PR that's cheap to review, take the dead-code pass
first: B.1 (`_run_search_phase`), B.2 (OpenAI/scaleway), B.6 (unused
imports), B.7 (stale `scripts/` sys.path) — net negative line count, no
behavior change, breaks no test. Confirms tooling is wired (`pytest`
green, `ruff` cleaner).

Then a config-fields pass: B.3 (`denied_tools`), B.4 (`gh_cli` — pick
"delete" or "wire up"), B.5 (`autonomy`). Each touches modes.yml,
modes.py dataclass, modes.py constructor, and one fixture in
`test_pr_feedback_classify.py:51-55`. Self-contained.

Doc-drift fixes (D.1-D.7) come for free with the dead-code pass — the
edits land in the same files. D.2 (the unenforced invariants) is the
juicy one: either implement the checks (3-5 line addition to
`_validate_invariants`) or delete the doc claims. Implementing them is
the safer call — they're load-time fail-closed and the test suite will
catch any mode-config that already violates them.

The WTFs split into "fix in one line" (A.1, A.7, A.10, A.12) and "needs
thought" (A.2, A.5, A.6, A.11). Take the one-liners; file the rest.

The refactorings (C.*) only pay off if you're touching those files
anyway. C.3 (single-source CLI→API tool-type map) is the highest-value
one because it directly addresses the structural class of bug behind
the recent v0.12.0 incident.
